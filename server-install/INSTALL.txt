MULTICORE SERVER 0.3.1 - SERVER INSTALL KIT  (mod id: multicore)
================================================================================
NOT installed on the server. Everything here is staged only.

WHAT IT DOES
Each dimension (South, Multiworld's shop/north/war/creative, hub, nether, end)
ticks on its own CPU thread instead of one after another. Mod code that has
not been checked as thread-safe (that includes Create Economy Money, Ranks and
the Launcher) still runs one at a time behind a shared lock, so those mods
work exactly as before.

NEW IN 0.3.1 (safety fixes, nothing to set up):
- Region threads: the empty squares around a region now belong to it. Before,
  a chest or vault just across a square edge from what uses it belonged to no
  region, and another region reaching into it (a Create stock ticker far away)
  did not pause the owner: items could be lost or duplicated. Fixed and tested.
- Create logistics (stock tickers, factory gauges, packagers, redstone
  requesters) now pause the other regions while they reach into vaults.
- Create's shared stress / redstone-link networks, belt and chute caches and
  brass tunnel scratch lists are made thread-safe (Create itself still runs
  behind the mod lock, as in 0.3.0).
- Optional, OFF by default and not recommended: threadSafeContent /
  regionSafeContent (run Create's machines without the lock) and unlockAllMods
  (every mod). Both were tested on the full pack and found unsafe; see README.
- A stalled shutdown now logs a thread dump.

NEW IN 0.3.0: REGION THREADS. A busy world (South) is split further: its
entities and block entities are grouped into regions at least 128 blocks
apart, each on its own thread, so players far apart in the same world no
longer wait for each other. /multicore regions off|on switches only that,
instantly. Step-by-step instructions you can give to an AI assistant (with
checkpoints where it must ask you first): INSTALL-FOR-AI-AGENT.md.

Server-side only. Players do NOT need it, and it must NOT go in the modpack or
the launcher's mirrorMods list.

TESTED WITH THE NEW MODS
  Tested with the full pack plus every Create Economy mod released since
  September (see the test notes at the bottom). Money, Ranks and the
  Launcher do their per-tick work on the main thread (server tick, commands,
  clicks); the one hook that runs on a dimension thread (cemoney's coin
  pickup) takes MultiCore's mod lock.

INSTALL (server stopped; take a backup of the world first)
1. Copy mods/multicore-0.3.1.jar into the server's mods/.
2. Leave dimthread installed for the first start. While its gamerule
   dimthread_active is true (the default), MultiCore stands by and does
   nothing, so the first start is the same as today.
3. ScalableLux + Sable: Sable 2.0.5 declares ScalableLux incompatible. If the
   server starts today it already has a way around this; nothing changes here.
4. Start. latest.log shows "[MultiCore]" lines saying it is standing by
   because dimthread is active.

TURNING IT ON (live, no restart; op level 3)
  /gamerule dimthread_active false     MultiCore takes over right away
  /multicore status                    mode, tick times per dimension
  /multicore locks                     which mods wait on the lock the most
  spark tps / /spark profiler          compare with before

AUTO-ADJUST (on by default, config [autoAdjust] in multicore-common.toml)
  Every 5 seconds MultiCore looks at how much each world costs:
  - A world with no players that costs under 0.5 ms (an empty Shop at night,
    the End) ticks on the main thread instead of waking its own thread. It gets
    its own thread back the moment a player enters or it costs over 2 ms.
  - If the server is lagging (over 50 ms per tick, TPS under 20) but running the worlds in
    parallel is not at least 1.05x faster than one thread for 30 seconds
    (everything stuck behind the shared mod lock), MultiCore ticks like vanilla
    for 10 minutes and then tries again. Each failed try doubles the wait, up
    to an hour. So it can never stay slower than vanilla.
  /multicore status shows each world's thread, average cost and players, plus
  the last decision and why. /multicore auto off|on switches it until restart.
  Region threads' work is counted too, so splitting South is judged correctly.

TURNING IT OFF AGAIN (instant, no restart)
  /multicore regions off               only region threads off
  /multicore off                       plain single-thread ticking
  or /gamerule dimthread_active true   back to dimthread
If MultiCore detects a threading error it logs it and switches itself to
single-thread ticking for the rest of the session (fallbackToSerialOnError).

REMOVING IT
  Stop the server and delete mods/multicore-0.3.1.jar. It stores nothing in
  the world.

ONCE IT HAS RUN WELL FOR A FEW DAYS
  Remove dimthread from mods/ (its NeoForge port gives almost no parallelism
  and stops some mods, such as Open Parties and Claims, from doing work during
  world ticks).

TEST NOTES (2026-11-24, 0.3.1, local test servers only)
  Pack: the 208 jars of 2026-11-15 plus the two poll mods Create: Aeroworks
  1.5.0 and RPG Prefab Houses 2.1.0 (210 jars). Full pack: 43/43 GameTests in
  the last 5 runs with the final code (plus fuzz test, no MultiCore-only
  errors), clean shutdown each time; 28 unit tests.
  TaCZ / Sophisticated Backpacks addon 1.0.0: CANNOT be added. It requires the
  mod id "tacz-1-21-1" (an unofficial TaCZ port); the pack's TaCZ 1.1.8 is
  "tacz", so NeoForge refuses to start the server. Not a MultiCore issue.
  Seen but not caused by MultiCore: 1 start in 13 of the dev test server
  failed in Create's Registrate ("unused register callbacks"; a real server
  only logs a warning there), then hung because some mod keeps a non-daemon
  thread pool alive.
  Open: a small Create-only test pack sometimes loses block drops in the nether
  in one regression test (also in 0.3.0; never seen in the full pack). Create
  logistics reaching a vault in ANOTHER DIMENSION is not paused (only other
  regions are); vanilla hoppers on that vault could race it.
